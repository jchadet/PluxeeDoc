Migration Glady → Pluxee — Documentation de transfert

Ce document décrit la migration de données Salesforce réalisée entre l'org source et l'org de destination, au moyen de l'ETL Talend Open Studio. Il s'adresse à l'équipe qui reprendra les traitements pour les rejouer, d'abord en recette puis en production.

Il décrit ce qui existe et pourquoi les choix ont été faits. Chaque affirmation est soit vérifiée dans les jobs livrés, soit signalée comme hypothèse à confirmer.

2. Périmètre

Ce qui est migré

JobObjets
MigrationPluxeeLead_v2 Lead, puis les Tâches et Événements qui leur sont rattachés
MigrationPluxeeOppoDevis Opportunité, Implementation__c, AssociationContactImplementation__c, leurs Tâches et Événements, et les Devis (Quote source → SBQQ__Quote__c cible)

Ce qui n'est pas dans ce périmètre

  • Comptes, Contacts et plateformes — traités par un job amont, porté par un autre périmètre. Il est le prérequis absolu : sans compte migré dans l'org de destination, aucune opportunité, aucun devis, aucun contact ne peut être créé, et toute la chaîne aval reste vide.
  • Lignes de devis (QuoteLineItem → SBQQ__QuoteLine__c) — non intégrées, voir la page 9.
  • Leads convertis côté source — exclus volontairement, voir la page 6.
  • Certains champs sans équivalent cible ou sans donnée source — détaillés dans les pages de décisions.

4. Ce qui est livré

  • Deux jobs Talend — MigrationPluxeeLead_v2 (34 composants, 3 sous-jobs) et MigrationPluxeeOppoDevis (59 composants, 8 sous-jobs).
  • La routine PicklistMapper — classe Java partagée du référentiel Talend, qui traduit les valeurs de listes de sélection d'une org à l'autre.
  • Le fichier CSV de correspondance des valeurs, lu par la routine au démarrage de chaque job.
  • La documentation générée par Talend pour les deux jobs — référence exhaustive, champ par champ, régénérable à tout moment depuis le Studio.
  • Le Permission Set de migration, déployé dans l'org de destination.
  • Le présent ensemble de pages.

5. Ce qu'il faut savoir faire pour reprendre

Trois compétences suffisent. Il n'est pas nécessaire d'être expert Talend :

  1. Installer et ouvrir Talend Open Studio, importer le projet et la routine.
  2. Changer les points de connexion pour pointer vers une autre org de destination (page 2, section « Bascule d'environnement »).
  3. Lire les fichiers d'erreur pour comprendre pourquoi un enregistrement n'est pas passé, et savoir ce qui relève de la technique ou du métier (page 8).

Le reste — mapping, cascades de listes de sélection, ordre des sous-jobs — est déjà en place et documenté dans les pages qui suivent.
