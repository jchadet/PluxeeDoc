8. Guide de reprise (run book)

Marche à suivre opérationnelle pour exécuter la migration. Cette page est faite pour être ouverte pendant un run, pas seulement lue une fois.

8.1 Prérequis dans l'org de destination

À vérifier une fois par environnement, avant le premier run. Un prérequis manquant ne provoque pas d'erreur : il produit des données incomplètes.

#PrérequisComment vérifierSi absent

Incident vécu — prérequis n°2. Lors d'une bascule vers un nouvel environnement, le champ IdGlady__c avait bien été déployé, mais sans droits d'accès au niveau du champ pour l'utilisateur d'intégration. Le champ étant invisible pour cet utilisateur, Talend l'a purement et simplement retiré des schémas à la reconnexion : les clés externes ont disparu des mappings, et une partie du paramétrage a dû être refaite. Toujours contrôler les droits d'accès aux champs avant de reconnecter les jobs à un nouvel environnement, et ne pas se contenter de vérifier que les métadonnées sont déployées.

8.2 Prérequis sur le poste de travail

  1. Talend Open Studio 8.0.1 installé, projet importé.
  2. Routine PicklistMapper présente sous Code > Routines globales.
  3. Fichier de correspondance des listes de sélection présent, en UTF-8, dans le répertoire pointé par resource_dir.
  4. Variables de contexte output_dir et resource_dir renseignées et pointant vers des répertoires existants et accessibles en écriture.
  5. Connexions Salesforce du référentiel à jour — voir la section 8.8.

8.5 Vérifier qu'un run est correct — les quatre contrôles

Un compteur de succès élevé ne prouve rien. Les trois mécanismes décrits en page 2 produisent des données incomplètes sans erreur ni rejet. Les quatre contrôles ci-dessous sont complémentaires : aucun ne remplace les autres.

Contrôle 1 — les volumes extraits

Sur le schéma du job, lire le compteur en sortie de chaque requête de périmètre. Un volume nul ou très inférieur à l'attendu désigne un problème dans la clause WHERE, pas dans le mapping. C'est le contrôle le plus rapide et celui qui évite de chercher au mauvais endroit.

Contrôle 2 — les fichiers de rejet

Ouvrir chaque fichier ..._ko.csv et regrouper par errorCode. La typologie renseigne immédiatement sur la nature du problème :

FIELD_CUSTOM_VALIDATION_EXCEPTIONRègle de validation de l'org de destinationVérifier le Permission Set ; sinon, arbitrage de mapping
INVALID_OR_NULL_FOR_RESTRICTED_PICKLISTValeur absente du jeu de valeurs cibleCompléter le fichier de correspondance ou déployer la valeur manquante

Contrôle 3 — la cohérence entre objets

Le contrôle que rien d'autre ne fait. Les jointures internes écartent les enregistrements orphelins sans les faire apparaître dans les fichiers de rejet (page 2). Seul l'écart entre le volume extrait et le volume inséré les révèle.

Contrôle 4 — le fichier d'audit du PicklistMapper

Ouvrir picklist_unmapped.csv après chaque run.

  • Les lignes unmapped sont des valeurs sans correspondance : le champ est arrivé vide. Chacune demande une décision — ajouter une correspondance, poser un défaut, ou déployer la valeur cible.
  • Les lignes defaut sont à surveiller : un volume anormal signale souvent une valeur mal orthographiée dans le fichier de correspondance, ou un cas métier oublié.

Le résumé affiché en console en fin de job donne la même information de manière condensée, par champ.

Contrôle complémentaire — les fichiers de données

Les fichiers ...Data.csv contiennent ce qui a été réellement envoyé, après mapping. C'est le seul endroit où vérifier qu'un champ donné part bien avec la valeur attendue — utile pour confirmer une correspondance ou diagnostiquer une colonne entièrement vide.

8.7 Rejeu, rattrapage et jour de bascule

Relancer après correction

Les sorties étant en insertion et non en mise à jour (page 5, T8), relancer un job sur le même périmètre retente tous les enregistrements. Ceux déjà migrés repartent en DUPLICATE_VALUE : aucun doublon n'est créé, mais les fichiers de rejet deviennent difficiles à lire.

Pour un rejeu propre après correction de mapping, deux options : supprimer les enregistrements concernés dans l'org de destination avant de relancer, ou restreindre temporairement le périmètre de la requête aux seuls enregistrements à reprendre.

Le jour de la bascule

Des enregistrements continueront d'être créés dans l'org source entre le dernier run complet et la mise en service. Un rattrapage est nécessaire.

  1. Identifier la date du dernier run complet.
  2. Ajouter une clause de date sur CreatedDate dans les requêtes de périmètre, pour ne reprendre que les enregistrements postérieurs.
  3. Relancer les jobs dans l'ordre habituel — comptes d'abord.
  4. Contrôler que les fichiers de rejet ne contiennent pas de DUPLICATE_VALUE : leur présence signale que la clause de date est mal bornée.

Alternative structurelle : passer les sorties en mise à jour sur IdGlady__c, ce qui rend le rejeu idempotent. Modification simple mais qui change la sémantique du run : à décider explicitement avant la bascule (page 5, T8).

8.8 Passer d'un environnement à un autre

  1. Vérifier les prérequis de la section 8.1 sur le nouvel environnement — en particulier les droits d'accès au champ IdGlady__c (prérequis n°2).
  2. Modifier la connexion Salesforce existante dans le référentiel : changer l'identifiant utilisateur, le mot de passe et le jeton de sécurité. Ne pas créer une seconde connexion : les 25 composants Salesforce référencent la connexion existante et devraient sinon être repointés un à un.
  3. Rouvrir un job et vérifier qu'aucun schéma n'a été altéré par la reconnexion — contrôler en particulier la présence de IdGlady__c dans les mappings.
  4. Vérifier les trois noms de record types (page 3, section 3.9) dans le Setup du nouvel environnement.
  5. Ajuster les variables de contexte output_dir et resource_dir.
  6. Faire un run de test sur un périmètre restreint, contrôler les quatre points de la section 8.5, puis retirer la restriction avant le run réel.
Après la migration de production, retirer le Permission Set de migration de l'utilisateur d'intégration pour restaurer les contrôles de saisie sur l'org.
